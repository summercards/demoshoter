# 工程文档入口

当前工程版本 **0.1.0**（以 `project.godot` 为准）。

## 这是什么工程

**初始化骨架工程。** 有能跑的 3D 底座、完整的工程规范、一批可复用的运行时模块；**没有已确定的玩法**。

主设计文档现在是一张空白骨架，只规定设计该写在哪、怎么冻结，不回答这个游戏是什么：

- [游戏设计文档 v0.1](v0.1/README.md) —— 先确认这一点，再往下读。

原《弹壳风暴2》的全部玩法设计、技术施工、审计与交付记录已归档，**不构成本工程的设计依据**：

```
docs/archive/inherited_shellstorm2_2026-10-21/
```

## 开始开发依次阅读

1. [游戏设计文档 v0.1](v0.1/README.md)：确认这是空项目，看懂设计槽位与冻结流程。
2. [骨架能力说明书](SKELETON_CAPABILITIES.md)：当前工程到底有什么能用的积木，哪些已被剥离。
3. [文档驱动开发规范](DOCUMENTATION_STANDARD.md)：怎么先定设计、再实施、再验证、再记账。
4. [工作区与目录规范](WORKSPACE_LAYOUT.md)：工程根、工程外产物出口与备份的约定；**动手写任何产物前先读这一篇**。
5. [功能契约索引](v0.1/MODULE_INDEX.md)：当前为空 —— 空白表本身就是「还没有功能」的答案，也是新增功能时的登记入口。

## 门禁

交付前必须运行：

```
python3 scripts/check_documentation_contracts.py
```

它检查：必需文档存在、三份主文档含工程版本号、文档内相对链接可达、功能索引与 `feature_registry.json` 一致、验证注册表/领域边界/功能追溯/媒体域四个子门禁。

**本工程的空状态是显式允许的**：`MODULE_INDEX.md` 声明空项目并列出零个功能时，门禁不报缺功能。一旦登记第一个功能，原有的六列行格式与可追溯性检查全部恢复生效。

文档检查不代替语义审查和运行验收。
